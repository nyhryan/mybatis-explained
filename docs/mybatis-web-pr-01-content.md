# PR 01 MyBatis 설명 원고 정리

작업 순서에서 첫 번째 PR입니다. 원고 검토를 마치면 [PR 02 정적 HTML 빌드](./mybatis-web-pr-02-build.md)에서 웹 문서로 변환합니다.

## 달성 목표

`docs/mybatis.md`에 담긴 대화 이력을 Java, Spring Boot, MyBatis XML Mapper, MySQL 8.x 환경의 주문 관리 예제로 재구성한다. 독자가 주문 처리 흐름을 따라가며 Java 메서드, Mapper XML, 실행 SQL이 어떻게 연결되는지 이해할 수 있도록 한다. 웹 빌드에 사용할 편집 원고는 `docs/mybatis-guide.md`에 작성한다. [대화 원문](./mybatis.md)

## 태스크

각 태스크의 완료 조건을 확인한 항목부터 `[x]`로 바꾸고, 필요한 검증 근거를 PR에 남긴다. 모든 태스크 완료 조건을 체크한 뒤 최종 완료 조건을 별도로 점검하고 체크한다.

### MYB-01-01 문서 흐름과 문체 정리

- [ ] 도입에서 예제 환경과 Service, Mapper 인터페이스, Mapper XML의 역할을 설명한다. 이후 주문 스키마와 매퍼 연결, CRUD, 동적 SQL과 매핑 규칙, 실무 점검 순으로 읽을 수 있다.
- [ ] 본문은 자연스러운 한국어와 일관된 용어로 작성한다. 대화형 인사말, 반복 요약, 검색 결과 표식과 공백 HTML 엔티티를 정리했다.
- [ ] 캐시를 제외한 원문의 주요 내용을 반영했다. 생성자 매핑이나 DB별 키 반환 방식처럼 본 흐름에 부가적인 내용은 짧게 설명하거나 공식 문서에서 찾아볼 수 있게 했다. [Mapper XML Files](https://mybatis.org/mybatis-3/sqlmap-xml.html), [Dynamic SQL](https://mybatis.org/mybatis-3/dynamic-sql.html)

### MYB-01-02 예제 연결과 경계 조건 검토

- [ ] 주문 생성은 생성 키를 주문 상품에 전달하는 흐름과 트랜잭션 경계를 보여 준다. 조회는 상세 `resultMap`, 조건 검색·페이징·건수 조회, 존재 여부, 여러 ID 조회를 다룬다. 수정은 버전 검사와 부분 수정, 삭제는 논리 삭제와 물리 삭제의 효과를 설명한다.
- [ ] 대표 예제의 DDL, Java 모델 필드, `@Param` 이름, 매퍼 `namespace`·`id`, SQL 별칭과 결과 매핑을 대조했다. `findByCondition`과 `countByCondition`이 같은 조건을 사용하고, 그 조건에 논리 삭제된 주문의 제외가 포함되는지 확인했다.
- [ ] `#{}` 바인딩과 `${}` 치환, 빈 ID 목록, 낙관적 락에서 영향 행 수가 0인 경우, 부분 수정에서 `null`이 뜻하는 동작을 예제 옆에서 설명한다. 동적 SQL은 대표 입력과 그때 만들어지는 SQL을 나란히 보여 준다.
- [ ] 각 코드 블록에 `java`, `xml`, `sql`, `text` 중 알맞은 언어와 문맥을 붙였다. 생략 기호가 포함된 조각은 어느 파일이나 구문에 들어가는지 알 수 있다.

### MYB-01-03 다이어그램 필요성 검토

- [ ] `users` → `orders` → `order_items`의 관계와 주문 생성 호출 흐름을 후보로 검토했다. 글이나 표로 이해하기 어려운 관계나 순서에만 Mermaid 원본과 한두 문장의 설명을 추가하고, 그림이 필요한 이유를 PR에 기록했다. 다이어그램을 생략했다면 관계와 호출 순서를 어느 절에서 설명하는지 기록했다.
