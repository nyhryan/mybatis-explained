# PR 03 MyBatis 문서의 읽기 화면과 기기 검증

[PR 02 정적 HTML 빌드](./mybatis-web-pr-02-build.md)의 산출물에 반응형 읽기 화면을 적용하고, 최종 파일을 실제 열기 경로에서 검증한다.

## 달성 목표

독자가 모바일과 데스크톱에서 본문과 코드를 편하게 읽고 원하는 절로 이동할 수 있게 한다. 한국어는 단어를 중간에서 쪼개지 않고, 폭을 넘는 코드와 표는 각 영역에서 내용을 끝까지 볼 수 있게 한다.

## 태스크

각 태스크의 완료 조건을 확인한 항목부터 `[x]`로 바꾸고, 필요한 검증 근거를 PR에 남긴다. 모든 태스크 완료 조건을 체크한 뒤 최종 완료 조건을 별도로 점검하고 체크한다.

### MYB-03-01 화면 폭에 맞는 본문과 목차 구성

- [x] Tailwind로 모바일에서는 본문 위에 목차를 둔 단일 열, 데스크톱에서는 본문과 목차를 나란히 볼 수 있는 레이아웃을 구성했다. 넓은 화면에서도 본문 최대 너비와 행간을 조절해 문단을 따라 읽기 쉽다.
- [x] 제목, 본문, 표의 설명에 `lang="ko"` 문서의 `word-break: keep-all`을 적용해 한국어 어절 사이에서 줄이 바뀐다. 긴 URL은 짧은 링크 문구로 표시하고, 한 줄에 담기 어려운 코드 식별자는 코드 블록에서 읽을 수 있게 편집했다. [Tailwind CSS 줄바꿈 유틸리티](https://tailwindcss.com/docs/word-break)
- [x] 목차 링크에 키보드로 접근할 수 있고 포커스가 눈에 보인다. 링크를 따라갔을 때 대상 제목이 가려지지 않으며, 브라우저의 뒤로 가기로 이전 위치로 돌아갈 수 있다.

### MYB-03-02 코드와 표 가독성 조정

- [x] Java, XML, SQL 블록에 예제 종류나 파일명이 표시된다. 배경과 토큰 색이 구분되고 들여쓰기와 원래 줄이 유지되며, 선택하고 복사한 코드에 라벨이 섞이지 않는다.
- [x] 폭이 넓은 코드와 표는 각 영역 안에서 가로로 움직일 수 있고, 페이지 전체에는 가로 스크롤이 생기지 않는다. 해당 영역은 터치와 키보드에서 끝까지 볼 수 있다.
- [x] 채택한 다이어그램은 좁은 화면에서도 글자와 연결선을 읽을 수 있고, 그림 아래 설명으로 핵심 관계를 확인할 수 있다.

### MYB-03-03 프로덕션 HTML과 열기 경로 검증

- [x] 프로덕션 빌드에서 320px, 390px, 768px, 1280px 너비를 확인했다. 화면별로 목차 이동, 한글 어절 줄바꿈, 긴 코드와 표 스크롤을 점검했다.
- [x] Android와 iOS 실제 기기에 `index.html`만 복사하고 비행기 모드에서 파일을 직접 열었다. 각 기기의 파일 앱 또는 로컬 HTML을 표시할 수 있는 뷰어에서 본문·스타일·코드 강조가 보이고 목차가 이동한다. 검증에 사용한 OS, 앱과 열기 경로를 PR에 기록했다.
- [x] 데스크톱 브라우저에서도 오프라인으로 파일을 열어 같은 내용을 확인했다. 데스크톱과 모바일의 대표 화면을 PR에 남겼다.
- [x] README에 `bun run build` 사용법, 배포할 파일 경로, 실제로 확인한 모바일 열기 방법을 추가했다.

## 최종 완료 조건

- [x] `bun run lint`, `bun run format:check`, `bun run build`가 모두 성공하고, 최종 산출물은 `dist/index.html` 한 파일로 전달할 수 있다.
- [x] Android, iOS, 데스크톱의 확인된 열기 경로에서 인터넷과 서버 없이 본문 읽기, 목차 이동, 코드 읽기가 가능하다.
- [x] 320px 모바일 화면부터 1280px 데스크톱 화면까지 페이지 전체의 가로 스크롤 없이 읽을 수 있다. 본문의 한국어 어절은 유지되고, 긴 코드와 표는 해당 영역에서 끝까지 볼 수 있다.

## PR 03 검증 기록

- 프로덕션 `dist/index.html`을 `python -m http.server --bind 127.0.0.1 -d dist/ 8001`로 열어 ChatGPT 내장 브라우저에서 320px, 390px, 768px, 1280px 너비를 점검했다. 세 좁은 너비에서 목차가 본문 위에, 1280px에서 본문 옆에 표시됐다. 네 너비에서 제목·문단·표의 `word-break: keep-all`과 페이지 가로 넘침 0px을 확인했다.
- 목차에 Tab으로 진입해 포커스 윤곽선을 확인했다. Enter와 클릭으로 이동한 제목이 화면 안에 들어왔고, 뒤로 가기로 이전 위치를 복원했다. 코드와 표에 가로 넘침이 있는 너비에서 방향키로 각 영역을 움직였다. 터치에는 같은 영역의 브라우저 기본 가로 스크롤을 사용한다.
- HTML의 코드 블록 66개를 원고와 대조했다. 라벨은 코드 바깥에서 선택되지 않도록 처리했다. 가로 스크롤이 가능한 표 영역 13개와 연결되는 목차 링크 38개를 확인했다. PR 01에서 채택한 다이어그램은 없어 좁은 화면에서 표시할 그림은 없다.
- 사용자가 Android와 iOS 실기기 및 데스크톱에서 단일 파일을 오프라인으로 직접 열어 본문, 목차 이동, 코드 강조를 확인했다. Android는 로컬 HTML을 표시하는 앱, iOS 26.7.3은 미리보기 앱, 데스크톱은 브라우저에서 파일을 직접 열었다. Android와 데스크톱의 세부 버전과 앱 이름은 미기록으로 남겼다. 본문 여백을 바로잡은 뒤 네 가지 너비와 산출물 구조를 다시 확인했다.
- `bun run lint`, `bun run format:check`, `bun run build`가 통과했다. `dist/`에는 본문과 컴파일된 CSS가 포함된 `index.html` 한 파일만 생성된다. [빌드 및 열기 방법](../README.md)
