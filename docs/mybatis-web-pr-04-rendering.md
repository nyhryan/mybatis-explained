# PR 04 MyBatis 문서의 본문과 Markdown 렌더링 수정

## 1. 목표

MyBatis 가이드 본문을 일반 문단으로 표시하고, 코드 블록 상단의 언어 헤더를 제거한다. 한글 조사와 붙어 있는 Markdown 볼드 구문은 본문 제목과 목차 양쪽에서 올바르게 렌더링한다. 기존 단일 HTML 오프라인 배포 방식으로 세 가지 수정 사항을 제공한다.

## 2. 태스크

### MYB-04-01 본문 문단의 박스 제거

**목표** · img1의 9.2절에서 `name` 파라미터를 설명하는 문단과 같은 유형의 본문을 일반 문단으로 표시한다.

**완료 조건**

- [ ] 현재 산출물에서 해당 문장은 `<p>` 안에 인라인 `<code>`가 들어 있는 구조다. 스크린샷을 재현하는 브라우저의 DOM과 계산된 스타일에서 박스의 출처를 확인하고, 원인에 맞는 수정 지점을 기록한다.
- [x] 9.2절의 대상 문단과 같은 유형의 문단에 테두리, 박스 배경, 모서리 장식이 보이지 않는다. 문단 간격과 `name`, `trim`의 인라인 코드 표시는 유지되고, 앞뒤 XML 예제는 각각의 코드 블록으로 표시된다.

### MYB-04-02 코드 블록의 언어 헤더 제거

**목표** · img2의 `XML` 헤더처럼 코드 위에 표시되는 언어 헤더를 공통 코드 렌더러에서 제거한다.

**완료 조건**

- [x] `vite.config.js`의 코드 렌더러가 `.code-label` 요소를 생성하지 않고, `src/style.css`에서 해당 요소의 스타일과 관련 주석을 정리한다. Java, XML, SQL, 일반 텍스트 예제의 첫 줄 위에 언어 헤더와 헤더 자리의 빈 공간이 없다.
- [x] Shiki 구문 강조, 줄바꿈, 들여쓰기와 선택할 수 있는 코드 내용이 유지된다. 긴 코드는 블록 안에서 키보드로 가로 스크롤할 수 있고, 스크롤 영역의 접근 가능한 이름과 포커스 표시가 유지된다.
- [ ] 실제 기기에서 긴 코드를 터치로 가로 스크롤할 수 있다.

### MYB-04-03 CJK 문맥의 Markdown 볼드 수정

**목표** · img3의 9.1절과 9.2절처럼 인라인 코드를 감싼 볼드 기호에 한글 조사가 붙는 구문을 Marked 파싱 단계에서 처리한다. 현재 저장소의 Marked에서 9.1절의 `**`가 그대로 표시되는 현상을 재현했다.

**완료 조건**

- [x] `marked-cjk-friendly`의 현재 Marked 및 Bun 빌드 환경과의 호환성을 대표 입력으로 확인한다. 호환되는 버전을 개발 의존성으로 추가하고 `bun.lock`을 갱신한 뒤, `vite.config.js`의 `Marked` 인스턴스에 등록한다. [markdown-cjk-friendly](https://github.com/tats-u/markdown-cjk-friendly) · [Marked 확장 문서](https://marked.js.org/using_advanced)
- [x] 9.1절과 9.2절의 제목 및 대응 목차 링크에서 `<where>`, `<trim>`, `<set>`이 `<strong><code>…</code></strong>`으로 출력된다. `**`는 화면에 드러나지 않고, HTML 태그 이름은 텍스트로 표시되며, 한글 조사는 강조 범위 밖에 놓인다. 목차 링크는 해당 제목으로 이동한다.
- [x] 회귀 검증에서 한국어 조사와 인접한 인라인 코드, 일본어·중국어 문장부호에 인접한 볼드는 올바른 `<strong>`으로 출력된다. 일반 `**bold**`도 계속 동작하고, 이스케이프한 별표와 인라인·펜스 코드 내부의 `**`는 리터럴로 유지된다. 표와 코드 렌더러도 기존대로 동작한다.

## 3. 최종 완료 조건

- [x] `bun install --frozen-lockfile`, `bun run lint`, `bun run format:check`, `bun run build`가 모두 성공하고 `dist/index.html` 한 파일을 생성한다.
- [ ] `dist/index.html` 한 파일을 네트워크 없이 직접 열어 본문, 코드 강조, 목차 이동을 확인한다.
- [x] 프로덕션 산출물의 모바일 320px 및 데스크톱 1280px 화면에서 9.1~9.2절의 문단이 일반 본문으로 표시되며 코드 헤더가 없고 볼드가 적용된다. 페이지 전체의 가로 스크롤 없이 긴 코드와 표는 해당 영역에서 끝까지 볼 수 있다.
- [ ] PR에 세 증상의 재현 위치와 수정 후 화면, CJK 회귀 검증 결과, 단일 파일 오프라인 확인 결과를 남긴다.

## 검증 기록

- 기존 `main`과 수정본을 각각 빌드해 브라우저에서 9.2절 문단을 비교했다. 두 버전 모두 `<article>` 바로 아래 `<p>`가 있고 계산된 테두리는 `0px`, 배경은 투명이었다. `name`, `trim`은 인라인 코드로 표시되고 앞뒤 XML 예제는 각자의 코드 블록에 들어갔다. img1의 박스가 재현되지 않아 원인 확인 항목은 열어뒀다.
- HTML의 코드 블록 66개에서 언어 헤더가 제거됐고 기존 빌드와 비교해 코드 텍스트가 모두 동일했다. 표 13개가 유지됐다. 320px 화면에서 코드와 표에 키보드 포커스가 보였고 방향키로 각각 가로 스크롤됐다. 320px과 1280px 모두 페이지 가로 넘침은 0px이었다.
- Marked 18.2.1과 `marked-cjk-friendly` 0.1.3으로 CJK와 일반 Markdown 구문 8건을 검증했다. 브라우저에서 9.1·9.2절 제목과 목차 링크 각각의 `<strong><code>` 두 개와 목차 키보드 이동을 확인했다.
- 브라우저의 `file://` 접근 제한으로 `python -m http.server --bind 127.0.0.1 -d dist 8766`에서 화면을 검증했다. 빌드 HTML의 스타일은 인라인이며 로드에 필요한 외부 자산 참조가 없다. 파일 직접 열기와 실제 기기 터치 스크롤은 미검증이다.
